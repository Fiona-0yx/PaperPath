## 0　背景与优先级

**为什么要做**：评委看的是 Agent。现在流程里的解释、测试大多是预设内容。目标是跑通一个真实闭环：

> 读论文 → 选中句子 → 大模型结合用户画像解释 → 操作被记录 → 画像里出现来源为"行为"的证据

**优先级【建议】**

| 级别 | 内容 |
| --- | --- |
| P1 必须 | 「问 AI」真实调用大模型（第 4 块） |
| P2 必须 | 行为记录（第 5 块）、时间轴（第 6 块） |
| P3 应该 | 四色划线（第 3 块） |
| P4 顺手 | 清理博客模板残留（第 8 块） |
| 有时间再做 | 画像页行为汇总、问整篇论文、章节目录与阅读进度、术语高亮 |

## 4　问 AI【已确认要做；具体形态为建议】

### 入口
- 选中文字后，浮层里的「问 AI」。
- 页面右下角「问这篇论文」，用于没有选中文字的整篇提问（替换模板残留的"聊天室"悬浮按钮）。【建议】
- 原来的「发送选句和上下文以解释」合并为「问 AI」打开后的第一个快捷问题。【建议，待确认】

### 界面
复用右侧栏，增加「问 AI」标签，与「笔记」并列：
1. 顶部引用刚选中的原文。
2. 快捷问题（一点就发）：用中文讲讲／举个例子／这句话在这一节起什么作用／我需要先懂什么。
3. 输入框，可继续追问，保留本次对话。
4. 每条回答下有两个按钮：**存入笔记**、**标记已解决**。

### 发送给模型的内容
- 选中的句子、所在小节、前后文、论文摘要
- 用户画像：英文阅读舒适度、当前困难、读完的目标等（取自入口采集）
- 最近若干条行为记录（例如刚把哪一句标成红色）
- 本次对话历史

### 回答的要求
- 带**原文依据**，区分"来自原文"和"模型补充"。
- 开头一行说明参考了画像的哪一条（例如"你提到英文阅读吃力，所以先给中文要点"），让用户看到画像确实改变了回答。
- 规则检查：引用的原文句子是否真的出自这篇论文。这只是规则检查，**不能说成做了语义事实核验**（沿用需求清单第 5 部分对 Critic 的说法）。
- 回答不对用户水平下结论。
- 调用失败时，显示"暂时无法回答"并保留用户的问题，**不能用预设内容假装回答**。

### 接口（沿用需求清单第 8 部分的 `POST /api/tutor`）

请求示例【建议】：
```json
{
  "paperId": "ml-01",
  "section": "1 · Introduction",
  "paragraph": 2,
  "selectedText": "It is tempting to treat this arrangement as bookkeeping.",
  "context": "…选区前后各一两段…",
  "question": "用中文讲讲",
  "history": [{"role": "user", "content": "…"}, {"role": "assistant", "content": "…"}],
  "profile": {
    "englishComfort": {"value": "吃力", "source": "用户自述"},
    "difficulty": {"value": ["公式", "生词"], "source": "用户自述"},
    "goal": {"value": "能向别人讲清楚", "source": "用户自述"}
  },
  "recentEvents": [{"type": "highlight", "color": "red", "text": "…"}]
}
```

响应示例【建议】：
```json
{
  "answer": "…",
  "profileBasis": "你提到英文阅读吃力，所以先给中文要点。",
  "citations": [{"quote": "…", "section": "1 · Introduction", "paragraph": 2, "verified": true}],
  "supplement": "…模型补充的内容，单独标注…"
}
```

### 服务端
- 大模型 API key **只放在服务端**，用 `.env` 保存，不能写进前端页面，也不能提交到 GitHub。
- 模型提供方：DeepSeek 为暂定。【待确认】
- 第一版不做流式输出，加载时显示"正在回答"。

### 提示词骨架【建议】
> 你是帮助本科生读论文的助手。回答只依据给出的论文片段；超出片段的内容必须标为"补充"。
> 先根据用户画像调整讲法：英文阅读吃力就先给中文要点，当前困难是公式就先讲符号含义，目标是"能讲清楚"就在最后给一句可复述的总结。
> 回答的开头用一句话说明参考了画像的哪一项。引用原文必须逐字摘录，并标出小节和段落。不要判断用户的水平。

## 5　行为记录【已确认要记录；字段为建议】

**要记录的事件**

| 类型 | 触发 | 附带内容 |
| --- | --- | --- |
| `open_paper` | 打开一篇论文 | 论文编号 |
| `view_section` | 离开或切换小节 | 小节、停留秒数 |
| `highlight` | 划线 | 颜色、选中文字、位置 |
| `unhighlight` | 取消划线 | 位置 |
| `bookmark` | 收藏 | 选中文字、位置 |
| `ask_ai` | 提问 | 问题原话、是否来自快捷问题、选中文字 |
| `save_answer` | 回答存入笔记 | 对应提问 |
| `mark_resolved` | 标记已解决 | 对应笔记 |
| `view_source` | 点查看原文 | 位置 |
| `finish_test` | 完成检测 | 检测编号 |

**一条记录的格式【建议】**
```json
{
  "id": "evt_0001",
  "time": "2026-11-28T10:30:00+08:00",
  "type": "highlight",
  "paperId": "ml-01",
  "section": "1 · Introduction",
  "paragraph": 2,
  "text": "…",
  "color": "red"
}
```

- 存放在浏览器 localStorage，键名沿用 `lunjing-journal-v1`，作为其中的 `events` 数组。【建议】
- 页面里加一句说明，告诉用户"会记录你的阅读操作，用于调整讲解"。【建议】
- 记录不得改变任何用户内容，也不能伪造不存在的操作。

## 6　时间轴【已确认保留】

- 用途：让用户看到自己的**学习路径**，也方便评委看到系统掌握了哪些行为。
- 内容：把第 5 块的事件按时间排出来：进入论文、读到哪一节、划线、提问、请求解释、标记已解决、完成检测。
- 按日期分组，每条带论文名和小节，点击可跳回原文位置。【建议】
- 位置：**放进「画像」页，做成一个标签页**，主导航保持三个按钮（路径／全景／画像，名称仍待确认）。【建议，待确认】
- 没有记录时显示空状态，不预置假记录。

## 7　行为对画像的贡献【建议】

遵守需求清单 0.7：一两次点击只支持**局部**判断，不推断整体水平；来源与"用户自述"、"答题证据"分开标注。

| 行为信号 | 对画像的作用 | 来源 | 把握度 |
| --- | --- | --- | --- |
| 同一概念反复标红或反复追问 | 记为"该概念尚未确认" | 行为 | 低 |
| 点了「标记已解决」 | 把上一条状态更新为"已解决" | 行为 | 低 |
| 提问类型累积（生词、公式、概念、结构） | 补充"当前困难" | 行为 | 低 |
| 用户的提问原话 | 作为用户自述保存，保留原话 | 用户自述 | 按原话 |
| 标绿（已理解）与后续检测结果相悖 | 后续可补一道短题验证（试读后置，现在只记录） | 行为＋答题证据 | 待验证 |

- **不能**把行为写成"基础差""水平中等"之类的结论。
- 画像页上这些条目要能追溯到原始事件。
