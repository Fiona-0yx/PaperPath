# 论径 · 读前测试的算法与生成流程

读前测试要回答一个问题：为了完成这次阅读目标，这位读者需要先懂哪些基础知识？系统选出值得测的知识点，每个知识点各出一道读前就能回答的题，并记录它对应的阅读目标，方便答完以后在相应位置补讲。

| 业务阶段 | 输入与处理 | 实现进度 |
|---|---|---|
| ① 生成读前测试（第 1–5 节） | 根据阅读需求定位原文，第一次调用模型提取候选考点，规则选考点，第二次调用模型结合画像出题。提交后按答案键判分。 | 已支持根据论文元数据出题和判分。原文段落定位待接入。 |
| ② 生成篇内读前画像（第 6 节） | 用规则合并原始画像、本篇阅读需求和逐题作答，输出固定结构的 `paper_profile`。此阶段只需读取已有考点关联。 | 已实现。 |
| ③ 回答文章问题（第 7 节） | 根据当前问题取回相关原文，参考篇内画像，由模型生成详略适合的回答。 | 待实现。 |

## 1. 读取论文、阅读方案和用户画像

| 输入 | 在出题时的作用 |
|---|---|
| 论文原文 | 目标流程接收 PDF 或已有的解析结果，根据阅读重点定位章节、段落或图注。如果上游已解析论文，可以直接复用文本及其位置。当前命令行支持题名、摘要和章节标题等元数据；只有题名时可生成主题层面的基础题。 |
| 阅读方案 | `focus` 指明阅读重点，`route` 给出精读或略读安排及每一步的目标，`depth` 决定理解深度。`pre_reading_test` 控制是否启用、题量和能否跳过。 |
| 用户画像 | 已学知识、阅读经验、语言和公式方面的困难，用来调整考点粒度、术语和问法。兴趣可以帮助选择例子，掌握情况由作答判断。 |

阅读方案是固定格式，程序直接读取字段。关闭读前测试时直接进入阅读。本次设计以 5 道题为例，实际生成时从本次配置读取题量。

## 2. 第一次调用大模型，从阅读目标倒推前置知识

这次调用产出一张候选考点表。对每个优先阅读目标，模型都要补全一句话：

> 为了让读者在阅读时能够**完成某个目标**，他需要先理解**某个基础概念**，因为**这个概念会在某一步用到**。

例如，阅读方案要求“精读方法，能讲清各环节如何衔接”。如果论文信息表明它研究预测模型，可以把“区分输入变量与预测目标”列为候选考点。掌握这个概念以后，读者就能带着“给模型什么、希望模型估算什么”去看方法部分。读前可以用独立的小例子考这个概念。

每个候选考点保留**概念、对应的阅读目标、为什么需要它、依据来自哪里**。在原文接入后，模型根据目标段落提取前置概念，程序校验所引文本能否在该段找到，并将论文标识、段落编号随入选考点保存；有页码时一并保存。这样既能解释为什么选这个考点，也方便问答时取回上下文。仅有元数据时，依据注明来自题名或摘要，原文位置留空。

## 3. 用覆盖优先的规则选出考点

采用贪心选择。每选入一个考点，就更新已经覆盖的阅读目标，再决定下一个考点。

1. **筛选候选。** 合并同义概念，剔除需要知道原文细节才能回答的考点，以及无法关联到具体阅读目标的考点。
2. **优先覆盖重点。** 优先考虑用户明确关注的重点和精读步骤。两个候选都很重要时，选能覆盖尚未涉及的目标、且与已选考点重复较少的那个。
3. **结合深度和画像取舍。** 同样是读方法，“能讲清楚”更需要理解环节之间的关系，“能复现”更需要理解操作条件。若两个考点同样必要，可依据已有学习或作答记录，优先测更有诊断价值的一个。
4. **按配置选满题量。** 如果需要 5 题，去重后只有 4 个合格考点，就让模型围绕尚未覆盖的目标补充候选，再按相同规则筛选。

## 4. 第二次调用大模型，按画像生成题目

把已选考点、各自的阅读目标和用户画像一起交给模型，一次生成整套题。第一版采用单选题。每题包含简短情境、一个正确答案、两个反映常见误解的选项和“不确定”。模型同时生成答案与解析，供提交后反馈使用。

个性化也可以发生在同一个考点内部。例如，同样测“输入与预测目标”，入门读者可以从生活场景中指出要预测的量；有建模经验的读者可以判断预测任务改变后，哪个变量应该改作预测目标。

## 5. 验题、判分并关联回阅读步骤

程序检查题量、选项、答案键，以及每题是否关联了考点和阅读目标。审查题目内容时回答两个问题：

- 没读过论文的人，能否凭基础知识和题干独立作答？
- 给定题干后，是否只有一个合理答案？

有歧义时只重出对应题目。提交后用答案键判分，结果只用于本篇论文的阅读辅助。

| 作答情况 | 对应的阅读辅助 |
|---|---|
| 答对 | 本次通过该概念检查，继续对应阅读步骤。 |
| 答错 | 记录该概念，在读到对应步骤时提供简短解释。 |
| 主动选“不确定” | 该概念记为拿不准，在关联步骤提供可选解释。 |
| 整体跳过测试 | 记录本次缺少作答证据，沿用阅读方案中的辅助设置。 |

## 6. 生成本篇文章的用户初始画像

篇内初始画像描述读者开始读这篇正文时的起点。它记录本次要读到什么程度、哪些前置概念已有作答证据，以及在哪个阅读步骤提供哪种帮助。

### 输入与合并顺序

1. 从本篇阅读方案取 `depth`、`focus`、`route` 和 `aids`，确定目标、路线和已选辅助。例如用户平时习惯略读，本次选择“能讲清楚”，就按本次目标安排阅读。
2. 从初始 `profile` 取与阅读相关的自述，如阅读经验、语言偏好和公式阅读困难。保留这些信息的来源。专业或兴趣只能帮助选择例子，概念掌握情况以本次作答为依据。
3. 读取本次测试的完成状态和逐题 `results`。每条证据包含题号 `id`、考点 `concept`、选项 `user_choice`、判定 `status` 和关联步骤 `reading_steps`。仅凭错题列表 `concept_gaps` 无法识别主动选择“不确定”的概念。

这些信息足以生成画像，无需再次传入论文全文或调用模型。将来接入原文后，可通过测试编号和题号追溯考点的原文位置。阅读步骤表示用户读到哪里需要帮助，原文位置表示支撑选题的文本在哪里，两者分别保存。

### 判定与阅读辅助

判分报告通过 `completion_status` 记录 `submitted`、`skipped` 或 `disabled`。整体跳过仍沿用逐题反馈中的 `unsure`，画像根据测试级状态将作答证据置空。对缺少操作状态、且全部为 `unsure` 的历史报告，画像生成函数使用 `unknown`。

| 测试状态与作答证据 | 写入篇内画像 | 对应的阅读安排 |
|---|---|---|
| 已提交，答对 | 该概念本次基础题通过，关联题号 | 按计划进入对应步骤，保留既定辅助。 |
| 已提交，答错 | 该概念建议先补，关联题号 | 按路线顺序，在第一个用到它的步骤前放一条简短解释。 |
| 已提交，主动选择“不确定” | 用户对该概念拿不准，关联题号 | 在关联步骤提供可选解释。 |
| 整体跳过 | 本次跳过，缺少作答证据 | 使用本篇原定的阅读辅助。 |
| 未启用测试 | 本次未测 | 根据初始画像和本篇方案开始阅读。 |

未被选入试卷的概念保留为未测。一次作答只更新它所测概念的篇内记录，例如答对一道预测目标题，仍可保留用户主动开启的公式讲解。

### 输出与用途

问答模块可从画像的 `answer_guidance` 读取本篇默认讲解方式。阅读深度决定默认展开到大意、可复述的关系，或复现步骤。开启公式讲解且读者自述容易卡在公式上时，`formula_guidance` 提示先讲直观关系再解释符号。对于当前问题涉及的已测概念，读取对应 `concept_evidence` 条目中的 `explanation_guidance`；未测概念按本篇目标处理。用户当次明确提出的详略要求优先。历史会话重新判分后会生成这些字段。

采用确定性规则生成结构化画像，随本篇阅读会话保存。画像包含本篇阅读目标、相关自述与辅助偏好、测试完成状态、逐概念证据和按步骤排列的辅助建议。有测试记录时保存对应的 `test_id`，便于从一条建议追溯到具体作答。阅读模块直接按步骤取用这些建议。如果页面需要一段自然语言导读，可让大模型润色已有结果。长期用户画像由独立流程维护。

**假设示例。** 某位读者本次想“讲清楚”净辐射估算论文，已在方案中开启公式讲解。假设他答错“净辐射”，答对“预测目标”，对“独立验证”选了“不确定”。若三题分别关联引言、方法和局限，生成的安排如下。

| 阅读步骤 | 读者将获得的帮助 |
|---|---|
| 引言 | 先用地表接收和向外传出的辐射解释“净辐射”，再读研究问题。 |
| 方法 | 直接进入模型框架，遇到公式时仍按方案提供讲解。 |
| 局限 | 提供可展开的“为什么要用独立数据验证”解释。 |

新建测试会将通过筛选但未出题的候选概念保存到 `untested_concepts`。整体跳过时，该列表也包含本次题目涉及的概念。旧记录只恢复实际保存过的信息。逐题证据中的 `why_needed` 和 `selection_evidence` 来自出题记录，分别说明为何要测、选择考点的依据。问答代码可调用 `guidance_for_concepts(profile, concepts, requested_detail=...)`，根据已识别的概念名取得相关建议。没有作答证据的概念统一返回 `unassessed`。

## 7. 根据篇内画像回答文章问题（待实现）

1. **根据当前问题取回原文。** 在本篇论文中查找能回答问题的段落、图表或公式说明。如果问题涉及已测考点，可用保存的原文位置找到上下文；问题超出五道题的范围时，仍在本篇全文中检索。具体数值、作者做法或结论应定位到对应出处。依据不足时，说明原文能支持到哪一步。
2. **选择相关画像证据。** 从 `paper_profile` 读取本篇阅读目标、辅助偏好和当前问题涉及的概念。答错过的概念先简短解释，通过基础题的概念可以直接用于说明，主动选“不确定”的概念可给一句提示。未测或整体跳过时，按本篇目标安排详略。
3. **生成自然语言回答。** 将当前问题、相关原文和选出的画像信息传给模型。用户当次明确要求“一句话概括”或“逐步推导”时优先遵循。画像采用固定字段，回答的篇幅、例子和展开顺序可以随问题改变。

例如，用户问“为什么估算蒸散量时要考虑净辐射？”时，先找到论文中说明两者关系的段落。如果用户在净辐射题上答错，可先用一句话解释净辐射，再结合原文讲两者的关系。如果用户已经通过该题并要求简答，就直接说明关系并给出出处。

## 如何验证这套流程

保留“阅读目标 → 前置概念 → 测试题”的对应关系。验证时每次只替换一个输入：

- **换论文**，检查考点是否贴合新主题，并仍然服务于原来的阅读目标。
- **换阅读需求**，检查题目的重点分配是否随精读目标和阅读深度变化。
- **换用户画像**，检查基础层级、语言和问法是否适合新用户。
- **换作答结果**，保持论文、方案和画像相同，只将一道题从答对改为答错，检查新增补讲是否只出现在该题关联的概念和步骤。再比较“全部主动选不确定”和“整体跳过”，前者应保留逐题自述，后者应记录缺少作答证据。

- **验证原文与问答（接入后）**，检查考点位置能否找回对应段落。保持问题和原文相同，只改变相关概念的作答记录，检查答案的事实和出处是否一致、解释深度是否恰当。

## 运行当前命令行

在项目目录执行 `python -m pip install -r requirements.txt`。打开同目录的 `llm.local.json`，在 `url` 填写 Chat Completions 完整接口地址，在 `model` 填写服务提供的模型名。需要鉴权时填写 `api_key`，否则保留空字符串。文件缺失或各项全部为空时，沿用环境变量 `PLAN_LLM_URL`、`PLAN_LLM_MODEL` 和 `PLAN_LLM_API_KEY`。当前命令行在**出题环节内部**两次调用模型，都会将论文元数据、画像与阅读目标发送至配置的服务。判分和画像合并在本地完成。

```powershell
python pretest_cli.py generate samples/example_input.json --plan samples/example_plan.json --count 5 --session session.json
```

终端输出学生试题和 `test_id`。新建的 `session.json` 是判分用的私有记录，含考点依据、正确答案和解析。省略 `--count` 时按方案题量出题，最多 5 道。省略 `--plan` 时使用现有阅读方案生成器。

作答文件示例（将 `test_id` 替换成本次生成的值）：

```json
{"test_id":"本次测试编号","answers":{"q1":"A","q2":"UNSURE","q3":"B","q4":"C","q5":"A"}}
```

```powershell
python pretest_cli.py grade session.json --answers samples/answers.json
```

方案允许整体跳过时，可用 `python pretest_cli.py grade session.json --skip`。判分输出逐题反馈、阅读步骤、待补概念和补讲建议，供本篇阅读会话使用。运行 `python -m unittest -v` 可执行离线测试。

提交或跳过后，同一会话文件保存最新的 `grading` 和 `paper_profile`。其中 `concept_evidence` 记录逐题证据，`step_support` 按路线列出补讲安排。再次提交时会重新计算并替换本次会话的结果。方案关闭测试时，生成命令直接返回基于画像和方案的阅读起点。

旧版会话在第一次判分时可补入出题当时的输入和方案，例如：

```powershell
python pretest_cli.py grade "samples/净辐射_测试记录_01.json" --input "samples/净辐射_测试输入.json" --plan "samples/净辐射_阅读方案.json" --answers samples/answers.json
```

如果缺少旧版的原始输入或方案，仍可按原命令判分，画像只使用会话中已有的辅助设置和阅读步骤，自述及缺失的阅读目标记为未知。

已有判分后，可单独导出本篇画像，直接使用保存的作答结果。下列命令创建新的 UTF-8 JSON 文件，原会话可继续使用。

```powershell
python pretest_cli.py profile "samples/净辐射_测试记录_01.json" --input "samples/净辐射_测试输入.json" --plan "samples/净辐射_阅读方案.json" --output "samples/净辐射_篇内读前画像.json"
```
