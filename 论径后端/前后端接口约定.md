# 论径前后端接口约定

核对日期为 2026-11-27。博客首页与 Python 算法已通过同源接口连接。首版沿用同源 `/api/reader/` 作为论径业务入口，先接通两篇论文的阅读记录，再独立接入方案和读前测试。「开始」继续打开初始画像手账，打开论文卡片直接进入阅读。

## 联调运行方式

博客开发服务、Vite 预览及 `blog-v3/server.js` 现在直接挂载同源 `/api/reader/`。在已安装依赖的 `blog-v3` 中运行 `pnpm serve` 即可使用。生产构建后可在同目录运行 `node server.js`。保留本仓库的目录结构，Node 使用 22.13 或以上，Python 需安装 `论径后端/requirements.txt` 中的依赖。可用 `LUNJING_PYTHON` 指定解释器。独立 Node 服务仍支持从 `复杂前端/lun-path` 运行 `npm start`。

| 已接入的入口 | 当前行为 |
| --- | --- |
| 机器学习基础 → 理解自注意力机制；神经网络 → 净辐射模拟与参考作物蒸散量估算 | 直接打开三栏阅读。选句、目录、问答引用、已记问题和移动端切换均使用同篇位置标识 |
| 阅读方案与测试 | 同源接口调用 Python 生成方案、编辑深度、生成题面、判分和返回篇内画像。浏览器只持有资源 ID 与学生题面；支持刷新恢复 |
| 个性化出题与在线解释 | 使用现有服务端模型配置。个性化出题默认调用模型；净辐射也可显式选择 `mode: "sample"`，使用已有五道样题。解释默认返回服务端原文检索，显式勾选在线模型后才发送选定问题与相关原文 |
| 阅读记录 | 新版事件以 eventId 排队与去重。当前浏览器的本篇摘要离线可看；服务端按匿名会话和论文汇总。画像封底改用个人总览 `GET /api/reader/me/overview`，保留全站旧端点供历史客户端使用 |

服务端通过 `GET /api/reader/session` 建立同源 HttpOnly 匿名 cookie。方案、测试和新版事件存放在 `复杂前端/lun-path/data/reader.sqlite3`，可用 `LUNJING_DATA_DIR` 替换数据目录。此身份以浏览器会话为单位，尚未关联博客登录账号。模型密钥保留在服务端。测试可运行 `node --test scripts/test-reader-api.mjs`（lun-path 目录）和 `python -B -m unittest discover`（论径后端目录）。

## 2. 接线前已有的 HTTP 接口

Node 服务默认绑定 `127.0.0.1:5180`。博客开发代理将 `/api/reader/` 原样转给它，通用 `/api` 则转博客服务并去掉前缀。健康检查须直接访问论径服务。新增 Python 能力由同一个业务入口转接，浏览器只依赖相对路径。生产部署也需配置对应转发。[Node 路由](../复杂前端/lun-path/server/index.mjs) · [博客开发代理](../blog-v3/vite.config.js)

| 方法和路径 | 请求与成功响应 | 当前限制 |
| --- | --- | --- |
| `GET /api/health` | 200，含 `ok`、`service:"lun-path"`、`scope:"vine-and-overview"` | 检查 Node 进程；不能据此判断 Python 或模型可用 |
| `POST /api/reader/events` | 每次一个 JSON 对象，必须有有效的 `kind`；写入 `data/reader-events.jsonl` 后返回 204 空体 | 16 KiB 上限，坏 JSON、非法对象、缺 kind 返回 400，超限 413，方法错误 405。当前按行追加，重复发送会重复计数 |
| `GET /api/reader/summary` | 200，含 `total,updatedAt,byKind,byAction,byPaper,byUser,byReason,weakTerms,topSections,papers,funnel,lifecycle,span,recent`；另支持 HEAD | 扫描整份日志，`recent` 最多 20 条。传入 paperId 或 userId 也不会触发过滤；不可直接用作个人报告 |
| `POST /api/reader/analyze` | 嵌入版已发送 `{paperId,text,context,section}`，期待读取 `explanation`，兼容旧字段 `summary` | 当前服务返回 404。前端把这条手记标为 `unavailable`；三栏原型的本地问答另行工作 |

当前事件白名单为 `kind,action,source,userId,noteId,noteType,filter,reason,resolved,status,crossPaper,paperId,paperTitle,categoryId,sectionId,sectionHeading,paragraphIndex,textLength,text,lang`。另取客户端毫秒时间戳 `at`，服务端补 `receivedAt`。现有 kind 为 `reader-open,menu-opened,menu-dismissed,action,analysis-status,filter,note-delete,note-resolve,note-jump`。当前客户端会上报最多 200 个字符的选区文本，`sendBeacon` 也无法向队列确认 204。两处都需在开启首版同步前调整。[事件发送与解释调用](../复杂前端/lun-path/src/reader.js)

历史开发记录里的 `/api/papers`、`/api/profile/update`、`/api/planner/next`、`/api/assessment`、`/api/tutor`、`/api/critic` 未在当前 Node 路由注册。竞赛文档中的动态追问、联网检索、Critic 属于产品设计或旧演示记录。[历史网页记录](../归档_未接入/旧后端/人工智能挑战赛/网页需求与开发记录.md) · [后端工作记录](工作记录.md)

## 3. 首版阅读采集协议

继续使用 `POST /api/reader/events`。新客户端发送 `schemaVersion:2`、唯一 `eventId`、本次打开论文的 `sessionId`、稳定 `paperId`、`contentVersion`、`kind`、`at`。事件时间均为 Unix 毫秒。书架再次打开同篇生成新 sessionId；重试复用原 eventId。服务端兼容旧事件，对新版按 eventId 原子去重，重复收到同一事件仍返回 204。旧事件没有稳定 ID，不能用于重放去重。

| 操作 | kind 与必要的业务字段 |
| --- | --- |
| 成功加载正文 | `reader-open`，`source` 取 `shelf / recommendation / direct` |
| 单段有效可见区间结束 | `paragraph-visible`，`sectionId,paragraphId,startedAt,endedAt,durationMs`。达到段落与视口较小高度的 50% 并连续满 1 秒，从首次达标起算。离页、切后台、切走正文、暂停或换论文时结算 |
| 选区稳定出现菜单、关闭、选择操作 | `menu-opened / menu-dismissed / action`，共用 `selectionId,range,textLength`；关闭附 `reason`，选择附 `action`。拖动调整期间不写事件 |
| 保存疑问、发送 AI 问题、解决或重开 | `question-saved / ai-question-sent / note-resolve`，传 `noteId,range`；解决与重开分别传 `resolved:true / false`。保存和发送分别计数，取消草稿只关闭菜单或编辑器 |
| 主动跳转 | 目录、问答出处用 `position-jump`，手记返回沿用 `note-jump`。两者都传 `source,from,to`；来源固定为 `toc / answer-source / note`，手记返回另传 `noteId`。一次动作只写一条跳转，落点以实际定位结果为准 |

`from/to` 为 `{paperId,sectionId,paragraphId}`。选区 `range` 为 `{start,end}`，端点各为 `{sectionId,paragraphId,offset}`。偏移以段落纯文本的 UTF-16 码元计，左闭右开，跨段保存两个端点。段落 ID 随内容发布，不能按本次渲染顺序临时生成。手记在本机另外保存原句、问题和内容版本，以便核对和高亮；失配则返回章节并提示“原文已更新”。旧手记只有章节时直接回章节。

例如净辐射的可见事件可以这样联调。`v1` 与 `season-p1` 为待两端登记的内容版本和段落 ID。

```json
{"schemaVersion":2,"eventId":"evt-001","sessionId":"read-001","paperId":"radiation","contentVersion":"v1","kind":"paragraph-visible","sectionId":"season","paragraphId":"season-p1","startedAt":1800000000000,"endedAt":1800000005000,"durationMs":5000,"at":1800000005000}
```

服务端须显式校验并保留区间和嵌套位置字段。新版事件排除原句、问题正文和上下文。先本地保存，经允许记录时排队，收到 204 再出队；网络或 5xx 重试，字段校验失败保留错误供核对。暂停期间手记照常保存。恢复记录使用新的可见区间。

**个人摘要。** 首版由本地事件计算。服务端个人版使用 `GET /api/reader/me/summary?paperId=radiation`，200 返回 `{paperId,visibleMs,paragraphs:[{paragraphId,visibleMs}],activeReturns:{toc,answerSource,note},resolvedNoteCount}`。整篇 visibleMs 取区间并集；resolvedNoteCount 按 noteId 最终状态计；自然滚动只影响可见区间。服务端按当前主体与论文共同筛选。匿名会话已用于绑定论径主体，博客登录账号的关联待实现，浏览器的 `lunjing-reader-uid` 只用作旧版统计标识。

## 4. 阅读方案、读前测试与问答接口

以下为前后端约定。方案、题目、判分与画像内部 JSON 保留 Python 已有的 snake_case；外围的 paperId、planId、revision 属于 HTTP 资源字段，进入 Python 校验前由适配层拆开。客户端只拿学生题面，完整测试会话和答案键留在服务端。

| 方法和路径 | 请求 | 成功响应及后端入口 |
| --- | --- | --- |
| `POST /api/reader/plans` | `{paperId,contentVersion,input}`。input 采用现有输入 schema，论文元数据须与所选论文版本一致 | 201 `{planId,paperId,revision:1,plan}`。保存输入快照，调用 `plan_generate(input)`。默认规则可离线运行 |
| `GET /api/reader/plans/{planId}` | 无请求体 | 200 返回同一方案信封，供刷新恢复 |
| `PATCH /api/reader/plans/{planId}` | `{revision,changes}`。changes 限 `depth,route,focus,aids`；路线从 1 连续编号 | 200 返回更新后的方案和递增 revision。调用 `edit_plan(input,current,changes)`；版本冲突 409 |
| `POST /api/reader/pretests` | `{planId,revision,count?}`，count 为 1–5 的整数。默认取方案题数与 5 的较小值 | 201 返回 `student_view(session)`，含 `test_id,skippable,questions:[{id,stem,options}]`。调用 `generate_pretest`，保存完整 session 与方案版本。禁用时题目为空且返回 paper_profile |
| `GET /api/reader/pretests/{test_id}` | 无请求体 | 200 返回同一学生题面。刷新复用已保存会话 |
| `POST /api/reader/pretests/{test_id}/grade` | 二选一：`{"answers":{"q1":"A","q2":"UNSURE"}}`（例为两道题）或 `{"skip":true}`。题号必须完整，选项为 A/B/C/UNSURE，跳过须 skippable | 200 返回 `grade_pretest` 的 `test_id,results,concept_gaps,completion_status,suggestion,paper_profile`。同一会话相同提交重放原结果，已判分后换答案返回 409 |
| `GET /api/reader/pretests/{test_id}/paper-profile` | 无请求体 | 200 返回该测试的 paper_profile。判分前返回 409，禁用测试可直接读取。一个用户对同篇论文的多次测试按 test_id 区分 |
| `POST /api/reader/analyze` | 兼容旧 `{paperId,text,context,section}`。新版传 `{paperId,contentVersion,range,question,text,context?,test_id?,requestedDetail?}`，发送前展示将发送的提问及引用 | 200 `{explanation,citations:[{paperId,contentVersion,range}]}`；原文证据不足时 citations 为空并说明。按论文目录返回带偏移的原文引用；显式传 `mode:model` 时调用在线模型，可按篇内证据调整解释。默认 `mode:retrieval` 返回原文摘录 |

新增路由统一使用 JSON，204 除外。沿用 Node 错误信封 `{"error":{"code":"…","message":"…"}}`。JSON 损坏用 400，字段、题号、选项或不允许跳过用 422，资源不存在或不属于当前主体用 404，状态或版本冲突用 409；生成服务不可用用 503，上游返回无法校验的输出用 502。生成失败保留已有方案，只有完整有效的题面才能建立可作答的测试。计划或测试的读取、修改均按会话主体授权。

方案内容按现有 [输入 schema](plan_input.schema.json) 和 [输出 schema](plan_output.schema.json) 校验。输出有 `depth,route,focus,aids,pre_reading_test,post_reading_test,warnings,assumptions,editable_fields`。步骤号用于测试与补讲关联，步骤中的 section 是显示文本；阅读跳转使用论文目录中的 sectionId。判分结果的 `mastered / gap / unsure` 只描述该题证据；整套 `skipped` 与逐题选 `UNSURE` 分开处理。篇内画像保留 `self_report,reading_plan,concept_evidence,step_support,answer_guidance,untested_concepts` 等字段。[方案实现](plan_generate.py) · [学生视图与判分](pretest.py) · [篇内画像](paper_profile.py)

## 5. 手账到算法的字段映射

取已提交快照的答案，按题目 ID 和选项值转换，不依赖当前中英文显示。封底编辑后的文本优先；只有可确认的枚举值进入受限字段，未知可省略。未确认推断、自由文本和自检证据保留在手账。两种前端复用相同的手账键，部署在不同源时浏览器数据各自独立。

| 手账 ID | input 字段 | 转换约定 |
| --- | --- | --- |
| education | profile.grade / major | 拆开年级、专业两组；只填已确认的部分 |
| purpose / direction | profile.primary_purpose / interests | “兴趣探索”转“兴趣”。方向传中文名称数组；现行单选目的没有 secondary_purposes 时省略 |
| reading | profile.paper_count / paper_language | 篇数按选项映射为 `0 / 1-3 / 4-10 / 10+`；“中英文都有”对应“差不多”。其他语言保持未知 |
| english | profile.english_comfort | 三档约定映射“逐句翻译 / 查词可读 / 基本无障碍”。前端中档原文是“借助翻译能理解大意”，这是近似映射，后续对齐问卷措辞 |
| python | profile.python_level | 当前四档按描述映射“不会 / 能看懂 / 能修改 / 能修改”。后两档都明确包含修改或实现能力；“能运行”用于明确仅能运行的自述 |
| difficulty | profile.stuck_points | 生词和术语→生词，数学公式→公式，文章结构→结构，不知道从哪篇开始→不知道读什么；规则按这些值触发辅助 |
| outcome | profile.default_depth | 看懂大意 / 能讲清楚 / 能复现 |
| intro / foundation | 本地原话 / 题目证据 | 输入 schema 不接收这两个键。用户确认的结构化字段另按上表传递 |
| 论文卡片与正文 | paper | 取 title、abstract、language、section_titles；has_formulas、has_code_link 按已知事实填。两篇验收材料使用原型章节；净辐射已有算法样例只提供题名和语种 |
| 本次阅读选择 | this_reading | purpose、depth、deadline 只在本次明确选择时覆盖默认值。算法记录缺失值采用的 assumptions，前端可展示 |

## 6. 联调验收
