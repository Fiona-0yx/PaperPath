# 论径前端与基础项目

一套可以实际操作的文献学习演示。界面以植物手账为主，串联学习入口、动态补问、画像确认、试读、藤蔓分支、论文书架、研读、理解检查和成长记录。

藤蔓页面现已恢复为完整 Sylva 页面：保留原始 3D 场景、原生液态金属按钮、浮动卡片、导航和入场动画。首页与学习花园共用同一实例，以轻量绑定替换文案和分支链接，去掉先前分屏、浅色渐变遮罩和另绘的 SVG 卡片地图。本次只修正藤蔓入口，书架、手账与学习服务保留现状。

藤蔓现在支持向下探索：页面提供约四屏的滚动行程，视角沿原来的藤蔓移动，依次经过研究基础、方法与实验、实践与复现。场景固定在视口中，原有分支入口随镜头推进并保持可点击；末端可以回到起点。滚轮、键盘翻页和单指滑动均映射到同一滚动进度，减少动态效果的系统设置下直接跟随进度。

## 本地运行

需要 Node.js 22 或以上版本。无需安装 npm 依赖。

在此文件夹打开终端，运行：

```powershell
npm start
```

打开 [完整项目](http://127.0.0.1:5180/)。`Ctrl+C` 停止服务。

开发时可用 `npm run dev` 监视服务端文件。修改前端后刷新页面即可。

## 推荐体验顺序

1. 首页点击“翻开学习手记”，自由介绍或直接进入问题引导。
2. 每轮回答后补问必要信息；“其他”、跳过和返回修改均可用。
3. 确认或修改初步画像，试读一段虚构英文论文。
4. 从学习花园进入一个方向分支，在书架选论文。
5. 打开论文，使用读前诊断、原文研读、带读、术语、原文证据定位与旁注。
6. 完成理解检查，查看局部证据和后续建议，收好本篇手记。
7. 回到花园和成长页，查看进度、待读与阅读记录；可导出或导入 JSON 手记。

首次访问没有预先编造的学习成绩。记录随着实际点击、回答与阅读操作产生。

## 界面语言与数据范围

- 中文模式：操作、提问、带读、反馈以中文显示；大分支保留小号英文副标题。
- 英文模式：操作与辅助界面使用英文。
- 论文标题、摘要、正文与原文引文始终保持其原语言，不因界面切换而翻译。
- 当前论文均为显式标注的虚构教学材料。模型、真实论文检索与 PDF 全文解析尚未接入；当前分支提问、抽取与评分使用可检查的模拟规则。
- 模拟资料以植物病害识别为主题。选择其他方向时保留用户目标，但不声称这些是该方向的真实推荐结果。
- 界面在桌面、平板与手机尺寸下响应式排列；尚不能将尺寸模拟视为真实 iPad Safari 验证。

## 项目结构

```text
lun-path/
├── public/
│   ├── index.html            页面入口
│   ├── styles.css            手账风格与响应式布局
│   ├── assets/               本地字体、植物插画与封面材质样式
│   ├── scenes/               适配后的藤蔓与 Three.js 书架
│   └── vendor/three/         Three.js r165 与许可证
├── src/
│   ├── app.js                路由、事件与学习流程编排
│   ├── views.js              各页面及学习工作台
│   ├── components.js         手账、封面等公共展示组件
│   ├── state.js              本机存储、迁移与格式检查
│   └── services.js           前端 HTTP 服务边界
├── shared/domain.js          双语模拟数据、分支规则与证据合同
├── server/
│   ├── index.mjs             静态文件与 JSON API
│   ├── adapters.mjs          模型与检索接入骨架
│   └── model-plan.mjs        尚待选型的功能职责
├── scripts/                  场景准备、依赖保存与浏览器验证
├── tests/                    领域、接口与迁移边界检查
├── references/               四份原始页面参考
└── docs/architecture.md      领域数据与 API 合同
```

前端通过 `src/services.js` 调用后台 API；后台使用共享的模拟领域层。后续可在保持页面合同的前提下接入模型和检索服务，而不需要先指定每个角色对应哪个厂商或型号。

详细接口见 [架构与 API](docs/architecture.md)。

## 数据保存

目标、回答、局部能力证据、待读、旁注、阅读位置与完成状态保存在当前浏览器的 localStorage。服务器不保存个人学习数据；没有账号或跨设备自动同步。导出 JSON 后，可在其他设备通过成长页导入。

“用户自述”和“答题证据”分别展示；未确认的信息保持未知，开放回答不直接判错。少量题目只支持局部判断，不生成整体能力分数。当前原文依据检查只确认引用与片段对应，不冒充真正的语义事实核验。

## 验证

```powershell
npm test
```

浏览器端验证：`node scripts/qa.mjs`，需要本机 Edge 和正在运行的服务；在独立测试浏览器配置中检查实际页面操作，截图和结果保存在 `qa/`。

仅验证藤蔓页面：`node scripts/qa-grove.mjs`，检查原场景全宽显示、原生入口跳转、首页与花园保留同一场景、中英文和小屏布局。

验证沿藤蔓滚动：`node scripts/qa-grove-travel.mjs`，实际发送滚轮和触屏输入，检查三个分支的聚焦与点击、路径末端返回及小屏布局。

真实模型、检索、长期数据库、账号与增强手势是后续接入项，当前保留清晰边界，不预设厂商分工。
